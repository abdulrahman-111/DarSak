# Tutoring Platform Implementation Plan

> **For agentic workers:** Execute task-by-task using the configured delegate fleet; orchestrator reviews and verifies each result.

**Goal:** Deliver the full bilingual tutoring MVP in PROJECT_PROPOSAL.md with real Supabase persistence and Vercel deployment support.
**Architecture:** One modular Next.js App Router application. Supabase Auth, PostgreSQL RLS, transactional RPCs and private Storage enforce the domain boundaries. Server actions use the user's session, not service credentials.
**Tech Stack:** Next.js, TypeScript, Tailwind, next-intl, Zod, Supabase, Vitest, Playwright.
**Spec:** docs/PROJECT_PROPOSAL.md, amended by the user's approval: non-commercial Vercel launch; no email delivery this stage; proceed autonomously.

## Global Constraints
- Arabic and English throughout; Arabic RTL and mobile layouts.
- All three education systems supported through database catalogue records.
- Email/password with confirmation disabled for this pilot. No password-reset UI claiming delivery; authenticated password changes supported. Document operator recovery and later SMTP setup.
- No public student records, self-promotion, cross-teacher writes, or unauthenticated private files.
- No payments, chat, AI, live video or homework submission in MVP, as the original idea defers these.
- Never claim cloud deployment or integration success without evidence.

## Review Focus
1. Concurrent acceptance into the last seat must yield at most one new member.
2. Student role spoofing and stale suspended sessions must fail database authorization.
3. Timetables must retain Cairo wall-clock time across DST and reject overlapping teacher lessons.
4. Removed students cannot obtain new private material downloads.
5. Missing environment variables, empty catalogues and failed mutations must produce usable screens and honest errors.

## File boundaries
- `src/app/[locale]`: public/auth/student/teacher/admin routes and composition.
- `src/features`: focused domain query, validation and mutation modules.
- `src/lib/supabase`: browser/server session clients.
- `src/i18n`, `messages`: locale routing and dictionaries.
- `src/components`: reusable accessible presentation.
- `supabase/migrations`, `supabase/seed.sql`: authoritative schema and starter academic catalogue.
- `tests`: unit, browser, and real database integration verification.
- `docs/implementation`: schema contract, decisions and progress.
