# Google Meet pilot: implementation contract

Baseline `83046cd`. Provider: Calendar API primary-calendar event with unique Meet conference per lesson. Scope `openid email https://www.googleapis.com/auth/calendar.events.owned`; no calendar metadata preflight. Backend handles unsupported conference responses. `APP_ENV=staging` works on the dedicated staging Vercel project's production deployment. Feature requires server enable flag, exact staging Supabase origin `https://dmbepdjwjmuelqcfzjae.supabase.co`, Google OAuth client/secret and server AES key; otherwise hard-disabled. No production configuration or schema application.

All ten public RPCs below use the **calling teacher's JWT**, never accept a teacher UUID, and constrain every lookup by `auth.uid()`. Private tables are in `dars_private`, not exposed via Data API. Explicit function revokes from PUBLIC/anon/service_role, grant only authenticated. Fixed `search_path`. Every teacher RPC requires live active role=teacher; creating/preparing/syncing additionally requires current teaching access/approval. Status/disconnect remain available after access expiry. Functions 7 and 10 have the exceptions described below. No service-role key needed.

## Exact RPCs

1. `google_meet_begin_flow(p_state_hash text, p_session_id uuid) -> void`
   Require session ID equals current JWT `session_id`. Replace owner's prior flow with hash (64 lowercase hex), owner/session, server timestamp + 10 minutes. One flow per teacher, throttle five starts per ten minutes using private counter. Cookie contains encrypted flow data; DB stores no verifier/token.
2. `google_meet_consume_flow(p_state_hash text, p_session_id uuid) -> boolean`
   Require current session ID match. Atomically consume the matching nonexpired owner/session flow by expiring it, returning true once and false thereafter. Preserve the start-rate window/counter across successful consumption. Require the session to remain present in auth.sessions for this user. Callback consumes before code exchange; failed exchange requires a fresh connect.
3. `google_meet_save_connection(p_google_subject text, p_google_email text, p_ciphertext text, p_key_version integer, p_scopes text[]) -> uuid`
   Return connection UUID. One current connection per teacher. Bounds on subject/email/ciphertext/scopes, required calendar scope. Ciphertext is versioned base64url envelope containing random nonce/tag, produced by server AES-256-GCM with AAD bound to teacher ID + Google subject + key version. Existing same-subject row may preserve its immutable connection UUID; changed subject is rejected until explicit disconnect. Every newly created/replacement connection gets a fresh random connection UUID. Server preserves omitted refresh token only for same Google subject by decrypting existing credentials first. Never save empty token as connected.
4. `google_meet_credentials() -> jsonb | null`
   Owner-only `{connection_id, google_subject, google_email, ciphertext, key_version, scopes, state}`; state `connected|reconnect_required`. Ciphertext may be retrieved by owner JWT but only server key decrypts it. No plaintext token stored or returned. Worker/callback can call this; UI uses status RPC.
5. `google_meet_disconnect() -> void`
   Disable connection, delete ciphertext/flow, mark owner's outstanding work blocked/disconnected. Preserve nonsecret event/connection identity history. Server reads credentials first, attempts Google revoke with short timeout, then invokes disconnect regardless of provider error. Google events remain teacher-managed after disconnect; existing cached link cannot be invalidated by DarSak.
6. `google_meet_status() -> jsonb`
   Owner-only `{state:'disconnected|connected|reconnect_required', email:string|null, pending_count:int, failed_count:int, unprepared_count:int}`. Never ciphertext. A disconnected teacher may read this even without teaching access.
7. `lesson_meeting(p_lesson_id uuid) -> jsonb | null`
   Owner gets `{mode:'automatic|manual', status:'unprepared|pending|ready|failed|reconnect_required|cancelled|disconnected', join_url:string|null, error_code:string|null}`. Accepted active students get only `{status,join_url}` for this lesson after fresh accepted enrollment and teacher availability checks. Other users including admins get null. Join URL only when scheduled + non-archived group + eligible teacher; never expose cancellation stale URL. No provider IDs/ciphertext. No cache/public projection/ICS additions.
8. `manage_lesson_meeting(p_lesson_id uuid, p_operation text, p_manual_url text default null) -> jsonb`
   Owner only. Operations `prepare|retry|manual|clear_manual`. `prepare/retry` require a future scheduled lesson in non-archived owned group and matching connected account; `manual` accepts bounded credential-free HTTPS URL validated again server-side; `clear_manual` suppresses URL and sets unprepared (does not auto-create). Increment desired revision on change. Manual/clear queues cleanup of old managed event if present and cannot be overwritten by an in-flight job. Return same owner shape as function 7. `retry` enqueues only eligible nonleased work and resets attempts explicitly, with teacher rate limit; it never creates an alternate random event ID after network ambiguity. Over pending cap raises stable `meeting_queue_full`; this must not roll back the already-created lesson.
9. `claim_google_meeting_jobs(p_limit integer default 1) -> setof jsonb`
   Clamp/reject outside 1..10; only caller-owned due jobs. Require current connection and teaching access for create/update; allow cancellation cleanup of already-owned events with connected credentials after access expiry. Claim with `FOR UPDATE SKIP LOCKED`, one active lease per lesson, 60-second lease; max pending cap100 and drain rate limit. Each row: `{job_id,lease_token,desired_revision,lesson_id,connection_id,operation:'upsert|cancel',event_generation:int,conference_attempt:int,provider_event_id:string|null,conference_request_id:string|null,title:string|null,starts_at:string|null,ends_at:string|null}`. Cancellation tombstones retain lesson/teacher/connection IDs even after lesson delete. Return no data from another owner. Worker fetches ciphertext once via function 4.
10. `settle_google_meeting_job(p_job_id uuid, p_lease_token uuid, p_revision bigint, p_outcome text, p_event_id text default null, p_conference_request_id text default null, p_join_url text default null, p_error_code text default null) -> boolean`
    Only owner with valid unexpired lease and matching connection identity. Outcomes `ready|pending|cancelled|retry|failed|reconnect_required`. Compare desired revision; stale results cannot publish URL, but retain a returned owned event ID so cleanup/reconciliation can find it; release/requeue latest desired work and return false. Event ID is bounded valid Calendar ID. Generated join URL strictly `https://meet.google.com/[a-z]{3}-[a-z]{4}-[a-z]{3}` without query/fragment. Server only supplies allowlisted safe error codes. DB owns attempts/backoff/next due time; automatic attempts max5. `pending` polls same event; it is not a failed creation and never produces another event. `reconnect_required` updates connection state and blocks further owner jobs. Settlement may record a provider result after access expiry; it must still check live active owner/session and lease. Result cannot be used to target another owner's job.

## Storage/lifecycle agreement

- `google_connections` holds one current owner connection; `google_oauth_flows` single-use hash; `lesson_meetings` holds per-lesson desired state, revision, owner, immutable connection ID, generation, manual URL, provider identifiers and pending cleanup identity; `google_meeting_jobs` is one coalesced row per lesson/identity. Keep cancelled/deleted tombstones until cleanup settles. No tokens in lessons/notes/materials/jobs.
- Transactional SQL triggers on lesson INSERT/meaningful UPDATE/DELETE enqueue upsert/cancel for automatic mode. Group archive/cancellation must suppress links and queue all managed future events. New future lessons auto-prepare only while owner connected and cap permits. Over cap: lesson succeeds, meeting is visibly unprepared. Generated lesson identity/timezones/exclusions unchanged. Copied lessons get their own meeting identity, never copied URL.
- Pending cap100 counts outstanding upsert/cancel jobs per teacher. Cancellation must not be dropped at cap: reuse existing coalesced row; if a ready event needs cleanup at cap, allow cancel row to supersede oldest unleased upsert (leave displaced meeting unprepared). Explicit preparation action processes at most ten own future lesson IDs per request and exposes partial progress/cap notice. No silent provider spend or unlimited drain.
- Worker batch at most10 and a strict total time budget (20s recommended); claim one at a time rather than hold ten leases. Use short HTTP timeouts and no long in-request backoff. Jobs not settled survive for the next teacher action/visit. One request-scoped teacher JWT only; never persist it. `after()` is an optimization, explicit authenticated Retry/Sync is the durable pilot recovery path. Do not mutate via a public GET route.
- Deterministic event ID = `dars` + SHA256 hex of deployment namespace + connection UUID + lesson UUID + generation. Conference request ID persisted before/at first request (or deterministic from same identity + conference attempt). Calendar insert `conferenceDataVersion=1`, primary calendar, private visibility, no attendees, guest invites/modifications off, minimal title, UTC times. On timeout/409 GET same event, validate private identity markers, then adopt; do not generate replacement. Reschedule patches same event; cancel deletes and accepts 404/410. Deliberately reinstating deleted/cancelled event increments generation. A confirmed conference failure followed by explicit retry increments conference_attempt and gives a new conference request ID.
- Reconnect to same Google subject may resume same connection identity if disconnected history retained and the teacher explicitly chooses it; simplest pilot default creates a new connection ID and does **not** automatically adopt old meetings. Different subject cannot manage old events. Show teacher manual management notice; worker never targets old IDs using new credentials.
- Keep errors as stable codes (`google_reconnect_required`, `google_permission_denied`, `google_conference_failed`, `google_rate_limited`, `google_unavailable`, `meeting_queue_full`, `meeting_unsupported`, `meeting_invalid_url`), with EN/AR UI mapping. Do not log Google responses, auth codes, cookies, ciphertext or decrypted tokens.

## Stateless cookie OAuth agreement

Server builds random state+PKCE verifier and encrypts `{state,verifier,user_id,session_id,locale,expires_at,redirect_uri}` in a 10-minute HttpOnly/Secure/SameSite=Lax cookie. Call function1 with hash(state), not plaintext. Callback verifies cookie AEAD, state, exact fixed callback URI, same live user/session; function2 consumes state before exchange. Then exchange code with client secret + verifier at fixed Google token endpoint; use the returned access token only server-side to call fixed `https://openidconnect.googleapis.com/v1/userinfo`, requiring nonempty `sub`, bounded email and `email_verified === true`. Treat that authenticated HTTPS response as Google account identity; do not parse/trust the returned ID token. No OIDC nonce/JWKS dependency is needed when no ID-token authentication is performed. Validate granted calendar scope before function3; encrypt refresh token server-side. Cookie is deleted on every outcome. Fixed locale integration return path only. No relationship with Supabase login provider tokens. Built-in crypto/fetch are sufficient; no new dependency required.

Real OAuth walkthrough blocked on owner-created Google Web OAuth client + Calendar API + exact stable staging redirect + consent/test users + preview-only secret/AES key. External Testing refresh tokens generally expire at seven days. No service-role key, billing, Meet API, recording, AI, or production credentials needed.

Required review tests: own-JWT isolation; active accepted-only join; cross-session/replayed state; encrypted credentials never plaintext; preview/local production-Supabase refusal including `NODE_ENV=production`; pending/timeout/409 reconciliation; concurrent retry; stale cancel/manual revisions; delete tombstone; cap100/batch10/attempt5; Google invalid_grant; generated/copy/group-cancel lifecycle. SQL migrations remain unapplied to hosted projects until reviewed separately.
