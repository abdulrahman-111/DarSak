# Administrative audit history

`dars_private.audit_log` is the private, append-only record for supported administrative changes. It keeps event time, the actor UUID and stored role when available, a fixed action and target category, optional request UUID, target UUID, and bounded structured metadata. It deliberately has no foreign keys: account deletion must not erase an event or its target identifier. A missing actor profile or a trusted background operation is recorded as `system`; account cleanup does not need a surviving user session.

The table has RLS enabled, no policies, and no table, identity-sequence, or writer-function grants to `PUBLIC`, `anon`, `authenticated`, or `service_role`. Its owner and the trigger functions are the only application write path. Inserts are checked at the table boundary for the action/category vocabulary and the small metadata key/value vocabulary. Do not add user supplied text or expand metadata with names, contact details, CV or meeting URLs, reasons, comments, report contents, payment references, manifests, or errors. UPDATE and DELETE are rejected by an ALWAYS trigger, and TRUNCATE has a statement trigger.

Canonical event sources:

| Action                                                   | Source                                                                                                          | Recorded target and metadata                                               |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `teacher_review_approved`, `teacher_review_declined`     | Insert of the corresponding decision in `public.teacher_review_events`                                          | Teacher UUID, review request UUID                                          |
| `teacher_application_changes_requested`                  | `public.teacher_applications.status` changes to `changes_requested`                                             | Application teacher UUID                                                   |
| `teacher_access_approved`, `teacher_access_declined`     | Decision transition in `dars_private.teacher_access_requests`                                                   | Access request UUID and status                                             |
| `fee_policy_changed`, `quota_policy_changed`             | Effective switch or time changes in the respective private policy row                                           | Policy category and enabled boolean                                        |
| `user_suspended`, `user_reactivated`                     | A real `public.profiles.status` transition                                                                      | User UUID and new status                                                   |
| `admin_granted`, `admin_revoked`                         | A real profile role transition into or out of `admin`                                                           | User UUID and new role; a simultaneous status transition has its own event |
| `feedback_approved`, `feedback_hidden`                   | Moderation status transition in `dars_private.group_feedback` by an active admin                                | Feedback UUID                                                              |
| `feedback_reply_approved`, `feedback_reply_hidden`       | Active admin changes reply fields through feedback moderation, including pending-only and published-only hiding | Feedback reply UUID. Student resubmission is excluded by the actor check.  |
| `report_resolved`, `report_reopened`                     | `public.reports.status` transition                                                                              | Report UUID and new status                                                 |
| `group_archived`, `group_deleted`                        | Real archive transition or group delete, including cascades during account cleanup                              | Group UUID                                                                 |
| `account_deletion_started`, `account_deletion_completed` | Queued insert and completed transition in `dars_private.account_deletion_requests`                              | User UUID, deletion request UUID, bounded state                            |
| `teacher_plan_assigned`                                  | Insert into `dars_private.teacher_plan_assignments`                                                             | Teacher UUID and plan code; transaction references are never copied        |
| `audit_purged`                                           | Successful owner retention call                                                                                 | Number of removed rows; system actor and null target                       |

Trigger execution is in the source transaction, so failed writes leave no audit event. Status predicates avoid no-op duplicates. Review decision events are sourced only from `teacher_review_events`, rather than mirrored profile or application approval fields. Fee and quota controls remain subject to their existing guards; no payment or push producer is added.

The owner retention function uses one transaction and an ACCESS EXCLUSIVE lock. It fixes a cutoff at the start of the call, temporarily disables only the row UPDATE/DELETE rejection trigger, deletes every row older than 24 months using the time index, restores that trigger as ALWAYS, and appends the removed-row count. It does not use TRUNCATE or a batch limit. A monthly `pg_cron` job runs at 03:00 UTC on day one. The lock and WAL volume can briefly delay ledger readers and writers; this full deletion ensures a backlog cannot persist. Owner DDL maintenance is the only immutability exception. The purge function has no execute grant to application roles, including `service_role`.

Account deletion removes the account's direct identifiers from normal application tables but intentionally leaves retained audit history, including pseudonymous actor and target UUIDs, until this 24 month cleanup. The history is not a consistent snapshot across separate read requests; UI pagination describes records up to its fixed timestamp cutoff.
