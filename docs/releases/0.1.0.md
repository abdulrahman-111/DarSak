# DarSak 0.1.0 — draft release notes

Status: preparation only; this document does not mean a release has been tagged or published.

DarSak is an Arabic/English teaching platform with teacher profiles, learning groups, enrollment review, lesson schedules, resources, and group assignments with private teacher feedback.

## Included in the readiness work

- MIT licensing for original project code, with bundled font notices preserved.
- A fixed test clock for booking proposal tests, preventing fixture dates from expiring in CI.
- Contributor and security guides, issue and pull request templates, and a public maintenance roadmap.
- Fresh local setup and independently owned hosted-backend instructions, plus opt-in synthetic demo data.

## Setup and verification

Follow [Development](../DEVELOPMENT.md) for local setup and [Deployment](../DEPLOYMENT.md) for your own hosted instance. Follow the [release checklist](../RELEASING.md) before publishing. The release commit, final test results, and screenshots must be added after verification.

## Known limitations

- The supported hosted setup uses a separately owned Supabase project. Fully self-managed production Supabase hosting has not been established by this checklist.
- The current launch policy accepts new lesson resources as links and disables new binary, avatar, cover, and CV uploads; existing objects may remain readable.
- Lesson scheduling uses Africa/Cairo time; this release does not offer arbitrary scheduling time zones.
- Auth email delivery, optional Google sign-in, Turnstile, notification email, and account-deletion workers require operator configuration.
- The optional demo contains known public credentials and synthetic data. Keep it local and disposable.
- The optional notification-email worker retains maintainer-specific sender and administrator recipient routing; independent operators must leave it disabled until adapted. Supabase Auth email has separate configuration.
- There is no security audit or guaranteed maintenance response time.
- Real adoption and independent deployment evidence must come from actual users; test fixtures and CI do not establish that evidence.
