# DarSak 0.1.0 validation record

Recorded on 23 October 2026. The annotated `v0.1.0` tag identifies the released source. Publication requires a passing main-branch CI run for that exact commit.

## Automated checks

The readiness implementation passed [CI run 39998268302](https://github.com/abdulrahman-111/DarSak/actions/runs/39998268302): formatting, ESLint, TypeScript, 731 Vitest tests across 125 files, production build, fresh Supabase migrations, pgTAP contracts, all 56 database fixture scripts, optional demo seed, and demo API smoke checks. The release preparation is checked again before merging and tagging.

The smoke test signs in as synthetic teacher, student, and administrator accounts, verifies canonical roles and accessible group/lesson/resource data, and confirms anonymous callers cannot read private lesson resources.

## Fresh clone and browser walkthrough

A separate clone was installed with `npm ci` and built with Node.js 24.19.0/npm 11.9.0. It used its own ignored local environment file and a separate disposable Supabase project on ports 55320–55326, not the maintainer's backend. No maintainer credentials or server-side service-role key were put into the app clone.

The backend used Supabase CLI 2.120.0, PostgreSQL 15.19, the checked-in migrations/reference seed, and the explicit synthetic demo seed. The cloud runner required slim images after the standard database image exceeded its extraction limit. A task-scoped Docker proxy configuration bypassed only local verification-service hostnames. The disposable stack used the default Auth template because custom template serving failed in this runner; confirmation stayed enabled, and existing repository/production email configuration was not changed. Docker still reported health warnings for some services, but the API and browser checks below completed. This does not verify email delivery or storage uploads.

Playwright with the installed Chromium verified:

- Teacher and student sign-in through the actual app forms in Arabic and English.
- Canonical teacher/student dashboard destinations after sign-in.
- The published synthetic mathematics group, its schedule, lesson, and accepted student roster in teacher management.
- The synthetic student's upcoming lesson in the selected timetable day.
- The published demo group in anonymous discovery.
- Anonymous teacher-route access redirects to sign-in in both languages.

Twenty desktop/mobile screenshots were captured after page headings and data loaded, in addition to four landing-page captures. The [screenshot index](../SCREENSHOTS.md) links them. All visible accounts and learning records are synthetic.

## What this evidence does not establish

This is automated verification by the maintainer's coding assistant on a managed runner, not a deployment by an independent human developer or a report of real user activity. The [independent setup issue](https://github.com/abdulrahman-111/DarSak/issues/76) remains open.

Email work was explicitly excluded by the maintainer. No email-worker/provider changes were made. Google OAuth, Turnstile, destructive deletion processing, a separately owned hosted backend, and full production infrastructure operation were not exercised in this walkthrough. These limits are included in the release notes.

See [Adoption](../ADOPTION.md) for the separate maintainer report of university use. No participant names or invented aggregate results are included.
